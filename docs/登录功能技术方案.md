# 登录功能技术方案

> 本文档整理大厂主流的登录技术方案，用于指导本项目（Spring Boot 3 + Java 21）登录功能的实现。

## 一、整体技术栈

大厂做登录，通常是「**一个安全框架 + 一种凭证方案 + 密码加密 + 可选验证码**」的组合。

| 维度 | 主流选择 |
|------|---------|
| 安全框架 | Spring Security |
| 凭证方案 | JWT（无状态）或 Session（有状态） |
| 密码加密 | BCrypt |
| 验证码 | 图形验证码 / 短信验证码 |
| 缓存 | Redis（存 token、验证码、Session） |

---

## 二、安全框架

安全框架是登录/鉴权的底座，负责拦截请求、校验身份、密码加密、权限控制等。

### 1. Spring Security（绝对主流）

- Spring 官方安全框架，Spring Boot 项目的默认选择、事实标准。
- 功能最全：认证（登录）、授权（权限）、密码加密、防 CSRF、会话管理等。
- 核心概念：
  - **认证（Authentication）**：验证"你是谁"（登录）。
  - **授权（Authorization）**：验证"你能干什么"（权限）。
  - **过滤器链（Filter Chain）**：请求进入时经过一系列过滤器完成鉴权。

### 2. Shiro（备选）

- Apache 出品，轻量、简单、上手快。
- 老项目 / 非 Spring 项目用得多，新项目使用率已下降。

> 结论：**用 Spring Security**，Spring 生态下的默认选择。

---

## 三、登录凭证方案（登录后如何保持状态）

### 1. Session + Cookie（有状态）

- **原理**：登录成功后，服务端在内存/Redis 存一份 Session，浏览器存一个 `JSESSIONID`，之后每次请求带着它。
- **适用**：传统单体应用、企业内部后台管理系统。
- **特点**：服务端要维护会话；多台服务器需共享 Session（常配合 Redis）。

### 2. JWT（无状态 token）⭐ 当前最流行

- **原理**：登录成功后，服务端签发一个带签名的 token（内含用户信息），客户端保存，每次请求放入 `Authorization` 头；服务端不存状态，靠签名验证 token 真伪。
- **结构**：`Header.Payload.Signature` 三段，用 `.` 分隔，Base64 编码。
- **适用**：前后端分离、微服务、App、跨系统。
- **特点**：天然无状态、易扩展；缺点是登出/吊销 token 麻烦（常配合 Redis 黑名单）。

### 3. OAuth 2.0 / OpenID Connect（第三方授权）

- **原理**：让用户用微信/QQ/GitHub/企业微信账号登录你的系统，系统拿到授权后换取用户信息。
- **适用**：第三方登录、开放平台。

### 4. SSO 单点登录

- **原理**：登录一次，多个系统都能用。
- **常用实现**：CAS、Keycloak、OAuth2 自建。
- **适用**：企业内部多系统统一登录。

---

## 四、登录方式（用户如何输入凭证）

- **账号 + 密码**：最基础。
- **手机号 + 短信验证码**：移动端大厂标配。
- **扫码登录**：PC 端微信/钉钉风格。
- **第三方登录**：微信 / 支付宝 / GitHub。
- **图形验证码 / 滑块**：防机器刷。

---

## 五、配套安全技术（几乎必用）

| 技术 | 用途 |
|------|------|
| **BCrypt** / Argon2 / PBKDF2 | 密码加密存储，**绝不能明文存密码** |
| **Redis** | 存 Session / 存 token 黑名单 / 存验证码（带过期时间） |
| 验证码 | 图形验证码、短信验证码 |
| 多因素认证（MFA） | 密码 + 短信/App 二次验证（高级安全场景） |

---

## 六、推荐方案（本项目）

结合项目现状（Spring Boot 3 + Java 21），推荐以下主流组合，这也是大厂前后端分离时代最常见的技术栈：

```
Spring Security   ← 安全框架（登录、鉴权、加密、拦截）
     +
JWT               ← 无状态 token（前后端分离标配）
     +
BCrypt            ← 密码加密（Spring Security 内置）
     +
Redis（可选）      ← 存 token、验证码、做登出
```

**为什么推荐这套**：它是目前前后端分离 + 微服务时代最主流的技术栈，学会这套后，再看 Session、OAuth2、SSO 都能快速迁移。

---

## 七、入门实现路线

先从「账号密码登录 + Spring Security + JWT」做起：

1. 建用户表和用户实体（引入数据库：MySQL + MyBatis-Plus / JPA）。
2. 用 Spring Security 做登录接口、密码加密（BCrypt）。
3. 登录成功签发 JWT，前端保存。
4. 写一个拦截器/过滤器，校验请求里的 JWT。

---

## 八、安全要点

- 密码必须加密存储（BCrypt），**禁止明文**。
- JWT 使用强密钥签名，密钥不能硬编码泄露到仓库。
- 验证码需设置过期时间，防止重放。
- 敏感接口（登录、注册）需防暴力破解（限流、锁定）。
